## What the API supports

`Export(nodeIds, format, outputPath, options?)` — the server rejects any other format
with this exact message:

```
Error: Second argument of Export operation must be one of png, jpeg, webp, pdf, html-tailwind, html-css!
```

So the complete list of export formats is:

| format | output | notes |
| --- | --- | --- |
| `png` | one `<nodeId>.png` per node | 2x scale by default (`options.scale`) |
| `jpeg` | one `<nodeId>.jpeg` per node | `options.quality` 1–100 |
| `webp` | one `<nodeId>.webp` per node | `options.quality` 1–100 |
| `pdf` | one multi-page `export.pdf` | all nodes combined |
| `html-tailwind` | one `.html` file | Tailwind markup; assets relative, never embedded |
| `html-css` | one `.html` file | inline-style markup; assets relative, never embedded |

There is **no** `svg` format, and no SVG serialization entry point in the `execute`
sandbox. Probed and confirmed missing: `GetSVG`, `ExportSVG`, `ToSVG`, `SerializeSVG`,
`ExportNode` (all `undefined`). The `execute` API surface is exactly:
`Insert, Copy, Update, Replace, Move, Delete, Generate, SetVariables, Get, GetVariables,
FindEmptySpace, Print, TakeScreenshot, Export`. No other Pencil MCP tool exports files
(`get_app_state`, `execute`, `get_style`, `read_skill`, `browser`).

`TakeScreenshot` returns base64 PNG only — not vector.

## Closest available output, for whoever picks this up

`Export([frameId], "html-css", out)` on a diagram frame emits an HTML document in which:

- every frame/rectangle/text node becomes an absolutely positioned `<div>` with inline
  `left/top/width/height`, `background-color`, `border-radius`, `outline`, font styles;
- every vector node (connectors, arrows, legends, `path`/icon nodes) becomes an inline
  `<svg viewBox="0 0 720 H">` with `<path>` elements — i.e. real vector geometry;
- text is `<div>` content, **not** `<text>`.

A converter could in principle turn that DOM into a self-contained SVG (720 wide,
`viewBox`, `<text>` for text, no `<image>`), but that is a renderer written by us, not a
Pencil export, and it was explicitly out of scope for this task. It is the only viable
route if SVG output is required.

Geometry note: raw `Export png` at `scale: 2` on `Vzg0E` (`Hình 1 · Architecture`,
720x320 design frame) produced IHDR 1442x642 — the 1px stroke is drawn half-outside the
frame on each side, so the exported bounding box is `width + 1` x `height + 1` design px.
Pencil's shipped WebP for the same frame (`L01-d1.webp`) is 1440x640, i.e. the bleed was
trimmed there. Any converter emitting SVG from `html-css` must account for this bleed.

Existing repo prior art confirms this: `D:/research/diagrams-v2/diagrams/*.svg` were
generated by `D:/research/src/60-flows.js`, not exported from Pencil; `D:/research/exports/pen`
contains only PNG exports (`L01.png` … `L23.png`).
