Tổng quan

Đây là hướng dẫn bàn giao để bạn (Justin, fullstack dev) dùng VPS Linux của Gdata Cloud (gdata.com.vn) từ máy Windows 11, sau khi skill gdata-vps đã được cài tại C:\Users\ADMIN\.omp\agent\skills\gdata-vps\ và bật trong skills.includeSkills. Skill tự load khi bạn nhắc gcloud, gdata hay gdata-vps — trong ngữ cảnh của bạn, "gcloud" nghĩa là Gdata VPS.

Gdata Cloud không phải Google Cloud.

Gdata là VPS Linux trên hạ tầng OpenStack, không có CLI/API chính thức. Google Cloud (GCP) là nền tảng hoàn toàn khác, dùng gcloud CLI. Hai thứ không liên quan — nhầm lẫn hai cái là sai lệnh ngay từ đầu.

Trong hội thoại với agent, từ gcloud mặc định trỏ vào Gdata VPS (nhánh SSH), trừ khi ngữ cảnh nói rõ Google (GCP, Cloud Run, App Engine, service account, project ID).

Điều kiện tiên quyết

Kiểm tra trước khi bắt đầu. Thiếu mục nào thì chỉ xử lý đúng mục đó.

  • Floating IP đã Associate (trạng thái Active trên portal).
  • Port 22 đã mở trong Security Group của Gdata.
  • File private key đã nhận qua email tiêu đề "Tạo SSH Key thành công".
  • Biết Floating IP và username (root).

Chưa có VPS? Xem portal: cloud-dashboard.gdata.com.vn → menu Cloud Server > Server > Tạo Server. Chưa có kết nối từ máy Windows? → Mục 5.

Kiểm tra sau khi SSH vào

Setup local (Windows 11)

Bước 1 — Nhận và lưu private key

Email tiêu đề "Tạo SSH Key thành công" kèm 2 file: id_rsa (private, giữ riêng) và id_rsa.pub (public, đã import). Lưu id_rsa về C:\Users\ADMIN\.ssh\ (đổi tên thành gdata_id_rsa để tách biệt):

powershell
mkdir -Force $env:USERPROFILE\.ssh | Out-Null
Copy-Item "$env:USERPROFILE\Downloads\id_rsa" "$env:USERPROFILE\.ssh\gdata_id_rsa"

Bước 2 — Siết quyền file key (icacls)

OpenSSH Windows từ chối key nếu ACL quá mở (lỗi UNPROTECTED PRIVATE KEY FILE). Chỉ user hiện tại được đọc:

powershell
icacls "$env:USERPROFILE\.ssh\gdata_id_rsa" /inheritance:r /grant "$($env:USERNAME):R"
icacls "$env:USERPROFILE\.ssh" /inheritance:r /grant "$($env:USERNAME):RX"
# Xác minh:
icacls "$env:USERPROFILE\.ssh\gdata_id_rsa"

Output phải chỉ hiện user hiện tại (và tối đa BUILTIN\Administrators) ở quyền R, không có Users/Everyone.

Bước 3 — Block Host gdata-vps trong ~/.ssh/config

Mở C:\Users\ADMIN\.ssh\config (tạo mới nếu chưa có), thêm block:

text
Host gdata-vps
    HostName <FLOATING_IP>
    User root
    Port 22
    IdentityFile ~/.ssh/gdata_id_rsa
    IdentitiesOnly yes
    ServerAliveInterval 30
    StrictHostKeyChecking accept-new
DòngÝ nghĩa
HostNameFloating IP public của VPS.
User rootUser Linux Gdata mặc định; đổi deploy nếu đã tạo theo bootstrap.
IdentityFileKey đã siết quyền; ~ resolve thành %USERPROFILE%.
IdentitiesOnly yesChỉ dùng đúng key này, không thử key khác trong agent (tránh "Permission denied" do key sai).
ServerAliveInterval 30Keepalive mỗi 30s, chống ngắt kết nối.
StrictHostKeyChecking accept-newTự nhận host key mới lần đầu; từ chối nếu host key thay đổi (phòng MITM).

Bước 4 — Test kết nối

powershell
ssh gdata-vps
ssh -o BatchMode=yes gdata-vps true; echo "exit=$LASTEXITCODE"

BatchMode=yes tắt mọi prompt — kết nối thành công trong chế độ này nghĩa là xác thực hoàn toàn bằng key, exit code 0.

Bước 5 — Chạy setup-ssh.ps1 (tự động hoá)

Script trong thư mục skill, idempotent, an toàn chạy lại:

powershell
powershell -NoProfile -File C:\Users\ADMIN\.omp\agent\skills\gdata-vps\scripts\setup-ssh.ps1 `
  -KeyPath "$env:USERPROFILE\Downloads\id_rsa" `
  -HostName <FLOATING_IP>
Tham sốBắt buộcMặc địnhÝ nghĩa
-KeyPathCó—Đường dẫn file private key nguồn.
-HostNameCó—Floating IP public của VPS.
-UserKhôngrootUsername SSH.
-AliasKhônggdata-vpsTên Host trong ~/.ssh/config.
-ForceKhôngtắtGhi đè block Host <Alias> cũ trong config.
-DryRunKhôngtắtChỉ in các hành động dự kiến, không ghi gì, không gọi ssh.

Hành vi: kiểm tra key tồn tại → copy về ~/.ssh\ → siết quyền bằng icacls → upsert block Host gdata-vps (idempotent) → test ssh -o BatchMode=yes -o ConnectTimeout=10 gdata-vps true, in PASS/FAIL kèm exit code.

Bootstrap server (lần đầu / đổi image)

Tất cả lệnh chạy trên server, user root, ngay sau khi SSH vào được. Chạy bằng bootstrap-server.sh (idempotent, có --dry-run):

powershell
ssh gdata-vps "bash" < C:\Users\ADMIN\.omp\agent\skills\gdata-vps\scripts\bootstrap-server.sh

Hoặc đăng nhập thủ công, scp script lên rồi bash /tmp/bootstrap-server.sh. Các bước script thực hiện:

1. Cập nhật hệ thống, timezone, hostname

bash
apt-get update && apt-get -y upgrade
timedatectl set-timezone Asia/Ho_Chi_Minh
hostnamectl set-hostname vps-app-01

2. Tạo user deploy

bash
useradd -m -s /bin/bash deploy
mkdir -p /home/deploy/.ssh
cp /root/.ssh/authorized_keys /home/deploy/.ssh/authorized_keys
chown -R deploy:deploy /home/deploy/.ssh
chmod 700 /home/deploy/.ssh && chmod 600 /home/deploy/.ssh/authorized_keys
# sudo NOPASSWD cho deploy (systemctl, docker, ufw, nginx, git, rsync)

Tắt phiên root, đăng nhập lại bằng ssh -i id_rsa deploy@floating-ip để xác nhận trước khi hardening.

Client SSH thay thế (không dùng OpenSSH)

ClientThao tác chính
PuTTYPuTTYgen → Load file id_rsa (chọn "All Files") → Export .ppk → PuTTY: Host = FIP, Port 22, Key = .ppk.
MobaXtermSessions → SSH → New session, Host = FIP, user = root. Advanced SSH setup → Private SSH key → chọn file id_rsa. Hỗ trợ thẳng key OpenSSH, không cần convert.

3. Hardening sshd

text
PermitRootLogin no
PasswordAuthentication no
PubkeyAuthentication yes
# Port 2222   # tùy chọn — chỉ đổi sau khi làm bước tiếp
Cảnh báo an toàn — đổi port sshd

Nếu đổi port (VD 2222): (a) mở port mới trong Security Group Gdata TRƯỚC khi đổi (Portal → Cloud Server → Security Group → Rule, TCP, port 2222, CIDR IP của bạn /32). (b) Giữ phiên SSH hiện tại (port 22) mở cho tới khi xác nhận đăng nhập phiên mới qua port mới thành công. Tự lockout do đổi port mà chưa mở SG là lý do thường gặp nhất.

bash
sshd -t
systemctl restart ssh

4. Firewall (ufw)

bash
ufw allow 22/tcp
ufw allow 80/tcp
ufw allow 443/tcp
ufw --force enable
ufw status verbose

SG Gdata là lớp 1 (portal), ufw là lớp 2 (OS). Cần cả hai.

5. Docker Engine + Compose plugin

Không dùng gói docker.io của distro — dùng repo Docker chính thức:

bash
install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/debian/gpg -o /etc/apt/keyrings/docker.asc
chmod a+r /etc/apt/keyrings/docker.asc
. /etc/os-release
echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] https://download.docker.com/$ID $VERSION_CODENAME stable" \
  > /etc/apt/sources.list.d/docker.list
apt-get update
apt-get -y install docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
systemctl enable --now docker
usermod -aG docker deploy
docker compose version

6. nginx, git, rsync, curl, fail2ban

bash
apt-get -y install nginx git rsync curl fail2ban

Fail2ban jail sshd — /etc/fail2ban/jail.d/ssh.local:

text
[sshd]
enabled = true
port = 22
filter = sshd
mode = normal
maxretry = 3
bantime = 1h
findtime = 10m
bash
systemctl enable --now fail2ban

Nếu đổi port sshd, sửa port trong jail rồi fail2ban-client reload.

7. Thư mục deploy

bash
mkdir -p /srv/app/releases /srv/app/shared
chown -R deploy:deploy /srv/app
chmod 755 /srv/app

releases/ — mỗi lần deploy theo timestamp. shared/ — config/đồ dùng chung.

8. systemd unit cho app

Mẫu /etc/systemd/system/<app>.service:

text
[Unit]
Description=<app> service
After=network-online.target
Wants=network-online.target

[Service]
User=deploy
Group=deploy
WorkingDirectory=/srv/app/releases/current
EnvironmentFile=/srv/app/shared/.env
ExecStart=/srv/app/shared/start.sh
Restart=always
RestartSec=5
StandardOutput=journal
StandardError=journal

[Install]
WantedBy=multi-user.target
bash
systemctl daemon-reload
systemctl enable --now <app>

9. Log rotation

Mẫu /etc/logrotate.d/<app>:

text
/srv/app/shared/logs/*.log /var/log/<app>/*.log {
    daily
    rotate 14
    compress
    delaycompress
    missingok
    notifempty
    create 0640 deploy deploy
    copytruncate
}

10. Kiểm tra sau bootstrap

bash
systemctl status <app> fail2ban docker nginx
docker run --rm hello-world
ufw status verbose
ss -tlnp | grep -E ':(22|2222|80|443)\s'

Xác nhận: hello-world OK, port mong muốn listening, ufw active, services active.

Rollback khi tự khóa SSH

Khôi phục qua Console portal

1. Portal Gdata → Cloud Server → Server → chọn server → Console (bàn phím web).
2. Đăng nhập bằng password (nếu đã đặt) hoặc key còn sống.
3. sed -i 's/^Port 2222/#&/' /etc/ssh/sshd_config rồi sshd -t && systemctl restart ssh.
4. Mở lại port cũ trong SG trước khi tắt port mới.
5. Làm lại hardening đúng thứ tự: mở SG → đổi sshd → giữ phiên cũ → xác nhận phiên mới.

Cheat sheet

Windows (PowerShell)

powershell
# Kết nối
ssh gdata-vps

# Setup SSH lần đầu (Windows)
powershell -NoProfile -File scripts\setup-ssh.ps1 -KeyPath "$env:USERPROFILE\Downloads\id_rsa" -HostName <FLOATING_IP>

# Deploy
powershell -NoProfile -File scripts\deploy.ps1 -Mode auto -RemotePath /srv/app -Service <app>

# Bootstrap server (lần đầu)
ssh gdata-vps "bash" < scripts\bootstrap-server.sh

# Kiểm tra service
ssh gdata-vps "systemctl status <app>"

# Rollback deploy
ssh gdata-vps "cd /srv/app/releases && ln -sfn <release-trước> /srv/app/releases/current && systemctl restart <app>"
